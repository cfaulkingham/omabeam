WebRTC media uses encrypted UDP. Signaling and JPEG fallback use HTTP. Browser decode and jitter-buffer times cover the latest sampling interval. Capture-ready timing starts after capture returns and excludes static-frame repeats. These measurements do not measure end-to-end latency. The viewer requests minimal buffering where supported; the browser may retain a larger buffer. H.264 uses 4:2:0 color; JPEG may preserve small colored text better. Odd image edges are padded by one pixel.

Sender measurements; network and browser buffering add delay. Frame age runs from encoding start to completed socket write, and is not display latency. Capture wait includes waiting for screen changes. Static content can report 0 fps.

Rates cover about 2 seconds; p50 / p95 show the median and 95th percentile of up to 256 samples from the last 5 seconds. Sent, skipped, bytes, and failures are session totals. Skipped frames were replaced by newer ones before sending.
